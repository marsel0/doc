Здесь собраны не все возможные ошибки платформы, а именно те, которые чаще всего нужны на этапе интеграции и отладки.

## Базовые ошибки

| Код | Что означает |
| --- | --- |
| `S10000` | Магазин неактивен |
| `S10002` | Create-запрос не успел вернуть ответ |
| `O10000` | Действие недоступно в текущем статусе |
| `O10001` | Недостаточно данных об оплате |
| `O10002` | Превышен лимит ордеров на одного клиента |
| `O10003` | Ордер не найден |
| `O10005` | Реквизиты не найдены |
| `O10008` | Клиент заблокирован antifraud-системой |
| `C10000` | Не найден курс обмена |
| `C10001` | Не найдена валюта |
| `B10000` | Не найден банк |
| `P10000` | Не найден тип оплаты |
| `T10000` | Не найден способ торговли |

## Как читать ошибки practically

### Если это `S10002`

- не создавайте новый ордер вслепую;
- сначала ищите существующий по `externalOrderId`;
- это особенно важно для `PayIn` и `Payout` create-методов.

### Если это `O10000`

- почти всегда проблема в текущем `status`;
- сначала дочитайте ордер;
- потом принимайте решение о следующем действии.

### Если это `O10005`

- для `H2H sync` это нормальный бизнес-кейс;
- предложите другой метод или другой банк;
- не считайте это системной аварией.
